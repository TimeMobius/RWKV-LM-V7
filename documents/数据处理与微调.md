# 从 JSONL 数据到 RWKV-7 微调模型

本文针对本仓库当前 `new_sft` 工作区，使用 `train.py`、`src/` 和配套启动脚本。先完成 [环境配置](./README.md)，然后按顺序操作。所有命令在仓库根目录执行。

主流程是：**准备模型和 JSONL → 用 chat template 渲染并分词 → 生成 token/mask binidx → 短跑验证 → SFT → 保存/续训 → 导出单文件权重**。

这里的微调是**全参数训练**。`D_DECAY_LORA` 等参数表示 RWKV 架构内部低秩矩阵的尺寸，不是 PEFT/LoRA adapter 微调开关。

## 1. 先认识文件和两种数据路径

| 入口 | 用途 |
| --- | --- |
| `data/make_sft_binidx.py`、`src/sft_binidx.py` | 对话 JSONL → 渲染模板、分词、packing/padding、token 与 loss mask |
| `data/SFT/sample/chat_template.jinja` | 本仓库的 System/User/Assistant/Tool 文本格式 |
| `data/tokenizer/rwkv_tokenizer.py` | 仓库自带 tokenizer，预处理默认 special-first |
| `data/make_data.py` | 普通 `{"text": "..."}` JSONL → 无 mask 的 binidx，供传统 PT 路径使用 |
| `src/dataset.py` | 读取 binidx、选择文档、构造下一 token 目标及右移后的 mask |
| `src/model.py`、`src/sft_loss.py`、`cuda/` | 模型、masked CE、融合 CUDA 算子 |
| `train.py`、`src/trainer.py` | batch/步数配置、DeepSpeed、学习率、日志、评估和 checkpoint |
| `run_3b_sft_zero3_offload.sh` | 2.9B 的模型参数检查和 SFT 启动包装 |
| `run_13b_sft_zero3_offload.sh` | 通用 SFT 启动后端，默认参数适配 13.3B |
| `run_3b_sft_profile.sh`、`run_13b_sft_profile.sh` | 短跑检查显存、速度和环境 |
| `scripts/convert_deepspeed_checkpoint_to_pth.py` | DeepSpeed 分片 checkpoint → 单个 `.pth` 权重文件 |

新手优先采用 **`sft_binidx` 对话微调路径**，不需要计算 `magic_prime`。`rwkv7_train_simplified.py` 和旧 demo 脚本是另外的实验入口，不是本教程使用的训练链路。

## 2. 准备原始 SFT 数据

### 2.1 文件格式

使用 UTF-8 JSONL：每行是一个完整 JSON 对象，不要把整个文件包在 JSON 数组中。字符串里的换行写成 `\n`。示例：

```json
{"messages":[{"role":"system","content":"你是一个用中文回答问题的助手。"},{"role":"user","content":"什么是监督微调？"},{"role":"assistant","content":"监督微调是使用输入和期望回答组成的数据继续训练已有模型。"}]}
```

要求和实际行为：

- 顶层有 `messages` 列表；常见角色为 `system`、`user`、`assistant`、`tool`。`system` 如存在应放第一条；建议显式提供自己的 system 文本，否则模板会注入带有 `xiaoke` 和 `CETC` 的默认身份。
- 至少包含一个 assistant；建议每条样本以需要训练的 assistant 回答结尾。多轮历史可以保留。
- **每条 JSONL 记录只对最后一个 assistant 的目标部分计算 loss**。更早的 assistant、user、system 和工具返回作为输入上下文。若想训练多轮中的每个回答，需要在预处理前把对话展开成多条、分别以各个回答结尾的记录。
- 模板在目标末尾写入 `<|im_end|>`，构建器再附加 `<|endoftext|>`，这些目标结束标记也参与训练。无思考回答前插入的空 `<think>\n\n</think>\n\n` 属于提示前缀。
- 有思考内容时，优先使用 `assistant.content` 中完整的 `<think>…</think>` 块。模板会去掉最后一个 user 之前的历史思考块，保留最后一个 user 之后的思考内容；最终是否训练仍由“最后一个 assistant”的边界决定。不要只因原始数据有 `reasoning_content` 字段就假定一定成功转换，要检查错误日志和输出。
- 尾部连续的 `tool` 消息会被移除，并写入信息事件；格式/渲染失败的记录会跳过。`--error-log` 同时可能包含信息事件和真正的错误，需要看 `skipped: true`，不能仅按日志行数认定失败数。

工具调用的数据结构示例：

```json
{"tools":[{"type":"function","function":{"name":"get_weather","description":"查询天气","parameters":{"type":"object","properties":{"city":{"type":"string"}},"required":["city"]}}}],"messages":[{"role":"system","content":"你是一个天气助手。"},{"role":"user","content":"北京天气怎么样？"},{"role":"assistant","content":"","tool_calls":[{"type":"function","function":{"name":"get_weather","arguments":{"city":"北京"}}}]}]}
```

`function.arguments` 可以是对象，也可以是合法 JSON 字符串，预处理会做规范化。上例训练工具调用；如果末尾再接 tool 返回和 assistant 最终回答，则最后的回答才是训练目标。不要自己提前拼接模板标记后再塞进 `messages`，否则可能重复渲染。

### 2.2 建议的目录布局

```text
RWKV-LM-V7/
  datasets/
    raw/                 # 自己的 JSONL，可含子目录和多个分片
    processed/           # 生成的 binidx
    cache/               # 可选的预处理缓存
  models/                # 下载或复制的单文件基础权重
  outs/                  # 训练、profile、导出结果
```

```bash
mkdir -p datasets/raw datasets/processed datasets/cache models outs
```

权重和大数据不随 Git 仓库提供。需自行取得兼容的 RWKV-7 `.pth`，放到 `models/`，或者使用自己的绝对路径。

## 3. 先用示例数据验证预处理

这个步骤只用 CPU，不需要模型。下面三个示例能检查单轮、多轮和中文处理；它们仅用于验证流程，不能用来训练有用的模型。

```bash
conda activate rwkv-lm-v7
export PYTHON_BIN="$(command -v python)"
export REPO_DIR="$PWD"
export CTX_LEN=2048
export VOCAB_PATH="$REPO_DIR/rwkv_vocab_v20260603.txt"
export CHAT_TEMPLATE="$REPO_DIR/data/SFT/sample/chat_template.jinja"

mkdir -p "$REPO_DIR/datasets/processed/example_ctx${CTX_LEN}"
export EXAMPLE_PREFIX="$REPO_DIR/datasets/processed/example_ctx${CTX_LEN}/train"

"$PYTHON_BIN" data/make_sft_binidx.py documents/examples/train.jsonl \
  --out-prefix "$EXAMPLE_PREFIX" \
  --vocab "$VOCAB_PATH" --chat-template "$CHAT_TEMPLATE" \
  --ctx-len "$CTX_LEN" --pad --n-epoch 1 \
  --num-workers 1 --no-shuffle \
  --error-log "$REPO_DIR/datasets/processed/example_ctx${CTX_LEN}/events.jsonl"

"$PYTHON_BIN" scripts/check_sft_mask.py "$EXAMPLE_PREFIX.mask" \
  --token-prefix "$EXAMPLE_PREFIX"
```

应看到 `docs=3`、`trainable_tokens>0`，检查工具输出 token/mask 文档数相同，mask 的 `unique` 为 `[0, 1]`。生成四个文件：

```text
train.bin           token 数据（uint16）
train.idx           token 文档索引
train.mask.bin      与 token 逐位置对应的 0/1 mask（uint8）
train.mask.idx      mask 文档索引
```

**训练的 `DATA_FILE` 填 `.../train`，不带 `.bin`、`.idx` 或 `.mask`。** mask 默认为 `DATA_FILE + '.mask'`。mask=1 表示该 token 作为预测目标时参与 loss，0 表示仅作上下文；训练读取时使用 `x=tokens[:-1]`、`y=tokens[1:]`、`target_mask=mask[1:]`，不需要用户手动右移。

检查实际训练目标和采样：

```bash
"$PYTHON_BIN" scripts/probe_sft_binidx_steps.py "$EXAMPLE_PREFIX" \
  --ctx-len "$CTX_LEN" --devices 1 --micro-bsz 1 \
  --accumulate-grad-batches 1 --probe-steps 1:3 \
  --vocab-path "$VOCAB_PATH" --show-text-chars 200
```

输出 `trainable_excerpt` 应包含最终回答而不是用户问题。该工具不加载模型，不能给出真实 loss。

## 4. 处理自己的完整数据

将自己的 `.jsonl` 放进 `datasets/raw/`。输入既可以是单个文件，也可以是多个文件或目录；目录会递归读取其中的 `.jsonl`。

```bash
export CTX_LEN=2048
mkdir -p "$REPO_DIR/datasets/processed/sft_ctx${CTX_LEN}"
export DATA_FILE="$REPO_DIR/datasets/processed/sft_ctx${CTX_LEN}/train"

"$PYTHON_BIN" data/make_sft_binidx.py "$REPO_DIR/datasets/raw" \
  --out-prefix "$DATA_FILE" \
  --vocab "$VOCAB_PATH" --chat-template "$CHAT_TEMPLATE" \
  --ctx-len "$CTX_LEN" --pack \
  --pack-strategy best-fit-decreasing --pack-shard-group-size 4 \
  --n-epoch 1 --num-workers 8 --worker-chunksize 64 \
  --shuffle --seed 1234 \
  --error-log "$REPO_DIR/datasets/processed/sft_ctx${CTX_LEN}/events.jsonl"

"$PYTHON_BIN" scripts/check_sft_mask.py "$DATA_FILE.mask" \
  --token-prefix "$DATA_FILE"
```

### 4.1 packing、padding、长度与内存

| 参数 | 效果 |
| --- | --- |
| `--pad --ctx-len 2048` | 每条原始样本独立补齐到 2049 token，便于检查 |
| `--pack --ctx-len 2048` | 将多条完整样本装进一个 2049 token 文档，剩余位置补齐 |
| `--pack-strategy best-fit-decreasing` | 按长度优先装箱，减少 padding |
| `--pack-shard-group-size 4` | 每次对 4 个输入 JSONL 文件一起装箱，不是每组 4 条记录 |
| `--n-epoch 1` | 预处理时只写一份数据，训练重复次数另行配置 |
| `--num-workers 8` | 预处理 CPU 工作进程数，不是 GPU 数量 |

`--pack` 和 `--pad` 二选一。这里使用 `ctx_len+1`，是因为训练输入和目标要错开一个 token。模型当前 CUDA 路径要求 **训练 `CTX_LEN` 为正的 16 倍数，`HEAD_SIZE=64`**。

超过目标长度的原始样本会被**过滤，不会自动切片或截断**。长度包括 system、历史、模板、回答和结束标记；因此调小上下文可能过滤很多长对话。当前 CLI 最后显示 `skipped_documents`，但不显示构建 API 返回的 `filtered_documents`，两者不同。不要把 `skipped_documents=0` 当成没有丢弃超长样本；需要保留全部长样本时，应先自行按对话轮次合理切分，或增大上下文后重新处理。

使用 `--pack/--pad` 后输出固定为 `ctx_len+1`。训练器也接受更短文档并补齐，但会拒绝更长文档。实际使用中让预处理和训练长度一致；从 2048 改到 8192、86016、192512 时，重新生成对应的数据集，不复用更长的旧文档。

packing 后，一个训练“文档”可能包含多条原始对话；步数按 packing 后的文档数计算。mask 只控制 loss，不提供样本之间的注意力/状态隔离；同一个 packed 文档中的后续样本能接触前面的上下文。

增大工作进程、每组文件数或单个 JSONL 文件大小都会增加内存。一个超大的单文件即使 `group-size=1` 也可能占用很多内存，建议先按行拆成合理分片。输出父目录须事先创建；重跑同一 `--out-prefix` 会重写产物，不要覆盖正在训练使用的数据。

### 4.2 大数据的缓存与中断重跑

```bash
mkdir -p "$REPO_DIR/datasets/cache/sft_ctx${CTX_LEN}"
"$PYTHON_BIN" data/make_sft_binidx.py "$REPO_DIR/datasets/raw" \
  --out-prefix "$DATA_FILE" \
  --vocab "$VOCAB_PATH" --chat-template "$CHAT_TEMPLATE" \
  --ctx-len "$CTX_LEN" --pack --pack-strategy best-fit-decreasing \
  --pack-shard-group-size 4 --num-workers 8 --n-epoch 1 \
  --no-shuffle --seed 1234 \
  --pack-cache-dir "$REPO_DIR/datasets/cache/sft_ctx${CTX_LEN}" \
  --error-log "$REPO_DIR/datasets/processed/sft_ctx${CTX_LEN}/cache-events.jsonl"
```

缓存必须配 `--pack --pack-strategy best-fit-decreasing --no-shuffle`。中断后重复同一命令，会重用完整的组缓存并重新合并最终文件；不是从半写入的最终 `.bin` 末尾追加。输入、词表、模板或长度改变后会按签名选择不同缓存。这里关闭预处理 shuffle，后面仍可开启训练时 shuffle。

## 5. 选择模型并校验结构

本仓库提供的两组默认架构如下；**最终以自己的 checkpoint shape 为准**：

| 参数 | G1J 2.9B | G1F 13.3B |
| --- | --- | --- |
| `N_LAYER` | 32 | 61 |
| `N_EMBD` / `DIM_FFN` | 2560 / 10240 | 4096 / 16384 |
| `VOCAB_SIZE` / `HEAD_SIZE` | 65536 / 64 | 65536 / 64 |
| `D_DECAY_LORA` / `D_AAA_LORA` | 96 / 96 | 192 / 192 |
| `D_MV_LORA` / `D_GATE_LORA` | 64 / 320 | 128 / 384 |

先选择 **一种**模型。2.9B 示例：

```bash
# 将权重文件放到这个路径，或把变量改成实际绝对路径。
export LOAD_MODEL="$REPO_DIR/models/rwkv7-g1j-2.9b-20260831-ctx16384.pth"
export TRAIN_LAUNCHER=run_3b_sft_zero3_offload.sh
export PROFILE_LAUNCHER=run_3b_sft_profile.sh

"$PYTHON_BIN" scripts/check_rwkv_checkpoint.py "$LOAD_MODEL" --json
```

改用 13.3B 时：

```bash
export LOAD_MODEL="$REPO_DIR/models/rwkv7-g1f-13.3b-20260415-ctx8192.pth"
export TRAIN_LAUNCHER=run_13b_sft_zero3_offload.sh
export PROFILE_LAUNCHER=run_13b_sft_profile.sh

"$PYTHON_BIN" scripts/check_rwkv_checkpoint.py "$LOAD_MODEL" \
  --expect n_layer=61 --expect n_embd=4096 --expect dim_ffn=16384 \
  --expect vocab_size=65536 --expect head_size=64 \
  --expect d_decay_lora=192 --expect d_aaa_lora=192 \
  --expect d_mv_lora=128 --expect d_gate_lora=384
```

2.9B wrapper 会自动校验 shape。13.3B 常规入口不自动推断所有架构，因此先运行上述检查。如果同一终端曾导出 `N_LAYER` 等变量，切换模型时也必须修改或取消它们，避免环境变量覆盖脚本默认值。模型文件名的 `ctx…` 只是原训练上下文提示，不表示更长上下文已经在新任务上验证过质量。

`rwkv_vocab_v20260603.txt` 是当前预处理默认词表。词表的 token ID 必须与模型对应；不要把任意 Hugging Face tokenizer 的 ID 当成本仓库 ID。shape 检查只能检查维度，不能证明词表语义匹配。

## 6. 设置硬件参数，先跑两步

下面以单机 8 卡为例。卡数不同需同时改 `CUDA_VISIBLE_DEVICES` 和 `GPU_PER_NODE`；单卡可写 `0` 和 `1`，但模型是否放得下需实测。

```bash
export CUDA_VISIBLE_DEVICES=0,1,2,3,4,5,6,7
export GPU_PER_NODE=8
export N_NODE=1
export MICRO_BSZ=1
export ACCUMULATE_GRAD_BATCHES=4
export STRATEGY=deepspeed_stage_3_offload
export TORCH_EXTENSIONS_DIR="$REPO_DIR/.torch_extensions"
export MAX_JOBS=4
export RWKV_CLEAN_STALE_EXTENSION_LOCKS=0
source scripts/setup_rwkv_cuda_env.sh
export TORCH_CUDA_ARCH_LIST="$("$PYTHON_BIN" -c 'import torch; print(";".join(sorted({"%d.%d" % torch.cuda.get_device_capability(i) for i in range(torch.cuda.device_count())})))')"

PROFILE_STEPS=2 PROFILE_MODE=none \
CTX_LEN="$CTX_LEN" LOAD_MODEL="$LOAD_MODEL" DATA_FILE="$DATA_FILE" \
PROJ_DIR="$REPO_DIR/outs/first-profile" \
  bash "$PROFILE_LAUNCHER"
```

这个 profile 不保存 checkpoint，也不启用 wandb。它使用独立的 profile 步数设置，不代表正式训练的 epoch 配置。确认进程实际完成 2 个 optimizer step、loss 为有限值、没有 OOM，再继续。

结果见 `outs/first-profile/train.log`、`profile_command.txt`、`gpu_monitor.csv` 和 `vmstat.log`。首次编译和初始化比后续 step 慢。`PROFILE_MODE=nsys` 需要额外安装 NVIDIA Nsight Systems，普通训练不需要。

本机文档曾记录 2.9B 在 8×H800 上短跑 `CTX_LEN=192512`；这不意味着小显存卡也能运行，或已经验证长时间稳定。首次使用从 2048/8192 等较短上下文验证，再为新上下文单独处理数据、重新 profile。

## 7. 正式进行 SFT

### 7.1 自动计算一遍数据

使用自己的正式数据 `DATA_FILE`，不要把第三节的微型示例误当成训练集。首次运行先关闭 eval，避免小数据划分后无训练文档。

```bash
export SFT_ONE_PASS=1
export SFT_TRAIN_SHUFFLE=1
export SFT_TRAIN_SHUFFLE_SEED=1234
export SFT_EVAL_TAIL_RATIO=0
export SFT_EVAL_TAIL_DOCS=0
export SFT_EVAL_EVERY_N_STEPS=0
export SFT_EVAL_STEPS=0
export SFT_EVAL_INCLUDE_IN_TRAIN=0
export LR_INIT=4e-6
export LR_FINAL=4e-7
export WARMUP_STEPS=10
export LR_WSD_DECAY_ITERS=0
export WEIGHT_DECAY=0.001
export GRAD_CP=1
export SFT_MASKED_CE_CHUNK=0
export SFT_MASKED_FUSED_CE_CHUNK=4096
export SAVE_EVERY_N_STEPS=100
export KEEP_LAST_N_CHECKPOINTS=3
export EPOCH_SAVE=1
export WANDB_PROJECT=""
export MASTER_PORT=29501

"$PYTHON_BIN" scripts/calc_sft_onepass_steps.py "$DATA_FILE" \
  --num-nodes "$N_NODE" --devices "$GPU_PER_NODE" \
  --micro-bsz "$MICRO_BSZ" --accumulate-grad-batches "$ACCUMULATE_GRAD_BATCHES" \
  --ctx-len "$CTX_LEN"

export PROJ_DIR="$REPO_DIR/outs/sft-run"
mkdir -p "$PROJ_DIR"
# 保存本次关键配置，便于在新终端续训。使用独立的新运行目录。
for name in REPO_DIR PYTHON_BIN CTX_LEN VOCAB_PATH CHAT_TEMPLATE LOAD_MODEL \
  TRAIN_LAUNCHER PROFILE_LAUNCHER DATA_FILE PROJ_DIR CUDA_VISIBLE_DEVICES \
  GPU_PER_NODE N_NODE MICRO_BSZ ACCUMULATE_GRAD_BATCHES STRATEGY \
  TORCH_EXTENSIONS_DIR TORCH_CUDA_ARCH_LIST MAX_JOBS RWKV_CLEAN_STALE_EXTENSION_LOCKS \
  SFT_ONE_PASS EPOCH_STEPS EPOCH_COUNT SFT_TRAIN_SHUFFLE SFT_TRAIN_SHUFFLE_SEED \
  SFT_EVAL_TAIL_RATIO SFT_EVAL_TAIL_DOCS SFT_EVAL_EVERY_N_STEPS SFT_EVAL_STEPS \
  SFT_EVAL_INCLUDE_IN_TRAIN LR_INIT LR_FINAL WARMUP_STEPS LR_WSD_DECAY_ITERS \
  LR_WSD_DECAY_STYLE WEIGHT_DECAY GRAD_CP SFT_MASKED_CE_CHUNK SFT_MASKED_FUSED_CE_CHUNK \
  SAVE_EVERY_N_STEPS KEEP_LAST_N_CHECKPOINTS EPOCH_SAVE WANDB_PROJECT MASTER_PORT \
  N_LAYER N_EMBD DIM_FFN VOCAB_SIZE HEAD_SIZE D_DECAY_LORA D_AAA_LORA D_MV_LORA D_GATE_LORA; do
  if [[ -v "$name" ]]; then
    printf 'export %s=%q\n' "$name" "${!name}"
  fi
done > "$PROJ_DIR/run.env"
set -o pipefail
bash "$TRAIN_LAUNCHER" 2>&1 | tee "$PROJ_DIR/console.log"
```

这些学习率只是低学习率起点，需要结合基座和验证集调整。`WANDB_PROJECT=""` 可关闭这两个常规 SFT 入口的 wandb。需要记录到 wandb 时设置项目名，并先 `"$PYTHON_BIN" -m wandb login`；离线模式可用 `WANDB_MODE=offline`。

**步数含义：**

```text
effective_bsz = N_NODE × GPU_PER_NODE × MICRO_BSZ × ACCUMULATE_GRAD_BATCHES
每个 optimizer step 的输入 token 数 = effective_bsz × CTX_LEN
一遍 optimizer steps = ceil(训练文档数 / effective_bsz)
```

例如 8 卡、每卡 1 条、累积 4 次，每次参数更新使用 32 个 packed 文档。1001 个训练文档会运行 32 step，共取 1024 个文档，尾部会从开头重复 23 个来填满 batch；“一遍”不是严格每条只访问一次。输入 token 数也不等于 mask=1 的训练目标数。

`SFT_ONE_PASS=1` 会覆盖传入的 `EPOCH_STEPS/EPOCH_COUNT`，运行自动计算的一遍。若要重复多遍，改为 `SFT_ONE_PASS=0`、把计算工具输出的 `epoch_steps` 填入 `EPOCH_STEPS`、再设置 `EPOCH_COUNT=3` 等。SFT 到达配置的 epoch 数会结束。

**学习率注意：** `LR_FINAL` 本身不会自动启动衰减。`LR_WSD_DECAY_ITERS=0` 且未设置 token 调度时，warmup 后维持 `LR_INIT`。想在最后 200 optimizer step 从初始值余弦衰减到最终值，可在启动前设置：

```bash
export LR_WSD_DECAY_ITERS=200
export LR_WSD_DECAY_STYLE=cosine
```

衰减区间超过总步数时，会覆盖整个有效训练区间。`SFT_MASKED_FUSED_CE_CHUNK=4096` 是 CUDA 融合 masked head CE；与普通 `SFT_MASKED_CE_CHUNK>0` 互斥。当前长上下文 ZeRO-3 推荐普通 chunk 保持 0，避免走已记录过超时的组合。

### 7.2 正式数据集上启用留出评估

数据量足够时，在第 7.1 节的启动命令前增加：

```bash
export SFT_EVAL_TAIL_RATIO=0.01
export SFT_EVAL_TAIL_DOCS=0
export SFT_EVAL_INCLUDE_IN_TRAIN=0
export SFT_EVAL_EVERY_N_STEPS=100
export SFT_EVAL_STEPS=5

"$PYTHON_BIN" scripts/calc_sft_onepass_steps.py "$DATA_FILE" \
  --devices "$GPU_PER_NODE" --micro-bsz "$MICRO_BSZ" \
  --accumulate-grad-batches "$ACCUMULATE_GRAD_BATCHES" \
  --eval-tail-ratio "$SFT_EVAL_TAIL_RATIO" --ctx-len "$CTX_LEN"
```

然后启动训练。`TAIL_DOCS>0` 时精确文档数优先于比例；默认留出的文档不参与训练。开启 `SFT_TRAIN_SHUFFLE=1` 时，划分来自固定 seed 的全量文档排列，验证集固定，不只是原文件最后 1%；训练文档每个 epoch 再按 seed+epoch 重排。

`SFT_EVAL_STEPS=5` 是每张卡评估 5 个 micro-batch，不保证遍历完整验证集。小验证集会循环重复；总训练步数小于 100 时不会触发这个评估间隔，可按数据量调小。`INCLUDE_IN_TRAIN=1` 会让评估文档也参与训练，这种结果不能当成独立验证集指标。

训练 loss 和 eval loss 都按有效 mask token 聚合。console 里出现 `SFT eval step ... loss ... ppl ... mask_tokens ...` 表示完成评估。这里的 PPL 只针对 SFT 目标，不与普通文本全 token PPL 直接等同。

### 7.3 日志与保存结果

```bash
tail -f "$PROJ_DIR/console.log"
ls -ld "$PROJ_DIR"/rwkv-*.pth
```

`train_log.txt` 记录运行参数、epoch 和评估信息；逐步输出可查 `console.log`，启用 wandb 时还可看曲线。`SAVE_EVERY_N_STEPS=100` 按完成的参数更新计数，不是 micro-batch 数；一遍少于 100 step 也会在 epoch 结束保存，如 `rwkv-0.pth`。

**DeepSpeed 模式下，`rwkv-step-100.pth` / `rwkv-0.pth` 通常是目录，不是单个权重文件。** 内部有 `latest`、模型分片和优化器分片。复制时带上整个目录；不要只拿某一个 rank 的 `.pt`。`KEEP_LAST_N_CHECKPOINTS=3` 会按时间保留最近的编号 checkpoint，step 和 epoch checkpoint 共用保留数量，旧的会被删除。

## 8. 中断后继续训练

复用原训练的模型结构、数据前缀、上下文、GPU/累积 batch、shuffle seed、eval 划分和 epoch 配置；将 `LOAD_MODEL` 指向保存完整的 DeepSpeed checkpoint 目录。程序会通过 `trainer.fit(..., ckpt_path=...)` 恢复优化器、global step 和训练进度。

在新终端先进入仓库根目录，并恢复第 7 节保存的配置：

```bash
conda activate rwkv-lm-v7
source outs/sft-run/run.env
source scripts/setup_rwkv_cuda_env.sh
set -o pipefail
```

13.3B 示例（替换成实际存在的 checkpoint）：

```bash
export LOAD_MODEL="$REPO_DIR/outs/sft-run/rwkv-step-100.pth"
test -d "$LOAD_MODEL"
bash run_13b_sft_zero3_offload.sh 2>&1 | tee -a "$PROJ_DIR/console-resume.log"
```

2.9B 的常规 wrapper 要求 `LOAD_MODEL` 是单文件，不能直接用它加载分片目录。续训时改用通用后端，并明确传入 2.9B 的架构：

```bash
export LOAD_MODEL="$REPO_DIR/outs/sft-run/rwkv-step-100.pth"
test -d "$LOAD_MODEL"
N_LAYER=32 N_EMBD=2560 DIM_FFN=10240 VOCAB_SIZE=65536 HEAD_SIZE=64 \
D_DECAY_LORA=96 D_AAA_LORA=96 D_MV_LORA=64 D_GATE_LORA=320 \
  bash run_13b_sft_zero3_offload.sh 2>&1 | tee -a "$PROJ_DIR/console-resume.log"
```

以上命令假定已恢复第 7 节的配置，不能只复制 `LOAD_MODEL` 一行。续训日志应包含 `Resuming trainer state from ...` 和恢复 global step 的信息。

常规入口使用 `train_stage=0`，显式加载给定目录。不要为了加载 `rwkv-step-100.pth` 改成 `train_stage>=2`：后者自动扫描的是 `rwkv-数字.pth` 等 epoch 名称，不扫描 step checkpoint。

已完成一遍的 checkpoint 在相同总步数下可能立即结束；完整恢复表示延续原训练计划。想从它开始一个新数据集/新训练计划，先导出单文件权重，再作为 `LOAD_MODEL` 启动新运行。单文件只恢复权重，不恢复旧优化器和步数。

需要人工中断前台任务时，可在其终端按 Ctrl+C；不保证中断瞬间额外保存，下一次从最后一个完整 checkpoint 恢复。仓库另有 `scripts/stop_rwkv_train.sh <launcher-pid>`，会向整个进程组依次发信号，使用前须确认 PID 属于目标训练且该进程组独立。

export CHECKPOINT_DIR="$REPO_DIR/outs/sft-run/rwkv-0.pth"

### 9.2 参考生成检查

"$PYTHON_BIN" scripts/run_converted_rwkv_demo.py \

## 10. 可选：先 PT，再 SFT

### 10.1 用相同对话 token 和全 1 mask 做 PT

这条路径仍使用 `data_type=sft_binidx`，仅把目标改成全 token loss。先生成正常 SFT 数据，再创建独立 PT 前缀，保留正常 mask 供 SFT 使用：

```bash
export PT_DATA_FILE="$REPO_DIR/datasets/processed/sft_ctx${CTX_LEN}/train_pt"
cp "${DATA_FILE}.bin" "${PT_DATA_FILE}.bin"
cp "${DATA_FILE}.idx" "${PT_DATA_FILE}.idx"
"$PYTHON_BIN" scripts/fill_sft_mask.py "${DATA_FILE}.mask" \
  --output-prefix "${PT_DATA_FILE}.mask" --value 1
"$PYTHON_BIN" scripts/check_sft_mask.py "${PT_DATA_FILE}.mask" \
  --require-value 1 --token-prefix "$PT_DATA_FILE"
```

注意全 1 包含 user、system、工具返回，**也包含原来 padding 的 token**。这和仅训练 assistant 的 SFT 目标不同；保留独立前缀，后续切回正常 mask。

本地提供 2.9B 两阶段专用脚本，示例中的步数显式设置为与当前默认一致的 1000/500。只有数据足够大、且确实想在同一确定性采样流中先 PT 再补完 SFT 时才使用：

```bash
export LOAD_MODEL="$REPO_DIR/models/rwkv7-g1j-2.9b-20260831-ctx16384.pth"
WANDB_MODE=offline \
CTX_LEN="$CTX_LEN" DATA_FILE="$PT_DATA_FILE" LOAD_MODEL="$LOAD_MODEL" \
PROJ_DIR="$REPO_DIR/outs/3b-pt" PT_STEPS=1000 SAVE_EVERY_N_STEPS=500 \
SFT_ONE_PASS=0 EPOCH_STEPS=10000 EPOCH_COUNT=1 \
SFT_TRAIN_SHUFFLE=1 SFT_TRAIN_SHUFFLE_SEED=1234 \
SFT_EVAL_TAIL_RATIO=0 SFT_EVAL_TAIL_DOCS=0 SFT_EVAL_EVERY_N_STEPS=0 \
  bash run_3b_sft_ctx192512_pt.sh

WANDB_MODE=offline \
CTX_LEN="$CTX_LEN" DATA_FILE="$DATA_FILE" \
LOAD_MODEL="$REPO_DIR/outs/3b-pt/rwkv-step-1000.pth" \
PROJ_DIR="$REPO_DIR/outs/3b-sft-finish" SFT_ONE_PASS=1 \
SFT_TRAIN_SHUFFLE=1 SFT_TRAIN_SHUFFLE_SEED=1234 \
SFT_EVAL_TAIL_RATIO=0 SFT_EVAL_TAIL_DOCS=0 SFT_EVAL_EVERY_N_STEPS=0 \
  bash run_3b_sft_ctx192512_sft-finish-onepass.sh
```

运行前重新把 `LOAD_MODEL` 指向原始 2.9B 单文件，而不是上一节的 checkpoint 目录或 13.3B 模型。脚本名字里虽然写着 ctx192512，实际使用可覆盖的 `CTX_LEN`。两阶段必须保持 token 文档和顺序完全相同、batch/seed/划分一致；第二阶段恢复 PT 的步数和优化器，并从采样位置继续，**不是从头再训练全部 SFT 数据**。

由于恢复位置依赖 epoch 长度，PT 需仍在首个 epoch 内，且已完成步数小于 SFT 一遍总步数；若 PT 已重复数据或跨过 epoch，不应把它解释为“补完同一遍”。先用 `calc_sft_onepass_steps.py` 检查总步数；小型示例不适用 1000-step PT。

专用两阶段脚本默认启用 wandb 项目，代码使用 `${WANDB_PROJECT:-RWKV7-3B-SFT}`，传空值仍会回到默认项目；上述示例使用 `WANDB_MODE=offline`。其默认 PT 是 **1000 step、每 500 step 保存**，不要照旧 README 中的 850/425 配置寻找 checkpoint。`ESTIMATED_STEP_SECONDS` 只影响说明文字，时长由实际吞吐决定。

如果需要“PT 后从头完整做一遍 SFT”，把 PT checkpoint 导出成单文件，再按第 7 节启动新 SFT 运行即可。

### 10.2 普通文本 PT 的传统路径

只有普通文本时，原始文件格式为每行 `{"text":"一段正文"}`，使用 `data/make_data.py`：

```bash
export TEXT_JSONL="$REPO_DIR/datasets/raw/text_train.jsonl"
mkdir -p "$REPO_DIR/datasets/processed/text_pt"
(
  cd "$REPO_DIR/datasets/processed/text_pt"
  "$PYTHON_BIN" "$REPO_DIR/data/make_data.py" "$TEXT_JSONL" 1 "$CTX_LEN" \
    --vocab "$VOCAB_PATH"
)
```

输出在**运行时工作目录**，名字取输入文件 basename，例如 `text_train.bin/.idx`，不是写回原始数据旁边。参数 `1` 是预处理重复次数；脚本还会输出总 token 数及当前上下文的 `magic_prime`。该脚本把普通文本载入内存并生成固定临时文件，不适合在同一目录并发处理超大数据。

后续传统训练需用 `--data_type binidx`，并按输出设置 `--my_exit_tokens`、`--magic_prime`、`--ctx_len`，同时传入正确架构。它与 SFT 的显式 epoch 调度不同：代码固定每个 mini epoch 为 40320 个样本，并从连续 token 流取窗口；更改数据或上下文必须重算 magic prime。日期版 PT 脚本多为机器上的历史实验配置，不是可直接套用的新手通用入口。普通对话微调按前面的 SFT 流程即可。

## 11. 常见问题

| 现象 | 检查和处理 |
| --- | --- |
| 找不到模型/数据 | 使用自己的绝对路径；`DATA_FILE` 无扩展名；确认四个 binidx 文件齐全 |
| `Full rendered text must start with ...` | 查看 events JSONL 的原始行；检查 assistant 思考字段、结束位置和模板，失败记录会被跳过 |
| 输出 0 文档或训练目标很少 | 检查 JSONL 结构、渲染错误、超长样本过滤和 `trainable_excerpt`，不要直接启动训练 |
| 文档长度超过 `ctx_len+1` | 用当前训练长度重新预处理；原始超长对话先合理拆分 |
| `size mismatch` / 缺参数 | 检查 checkpoint 架构及是否把分片文件误当成完整权重；不要用 `load_partial` 掩盖模型结构错误 |
| `nvcc`、header、`-lcurand/-lcublas` 缺失 | 检查环境配置步骤，显式设 `PYTHON_BIN` 后 source CUDA 环境脚本 |
| `Trainer.add_argparse_args` 不存在 | 检查是否错误安装了 Lightning 2.x，本仓库固定 1.9.5 |
| OOM | 先减 `CTX_LEN` 并重做数据；`MICRO_BSZ=1`、`GRAD_CP=1`、ZeRO-3 offload、fused CE；累积 batch 不能替代单次前向所需显存 |
| 刚启动很久没 step | 看是否仍在 nvcc/CPUAdam 编译、模型加载或读 checkpoint；查看 profile 日志，别把首次初始化时间当成 step 耗时 |
| 续训又从头走数据 | 确认加载的是完整分片目录、策略仍为 DeepSpeed，且未改 batch、seed、epoch 配置；单文件加载只恢复权重 |
| 学习率一直不降 | `LR_FINAL` 需配合启用 WSD 等调度；检查 `LR_WSD_DECAY_ITERS` 是否为 0 |
| 多个任务端口冲突 | 为本任务修改 `MASTER_PORT`，同时使用独立输出目录 |

排查 loss 时可使用 `scripts/probe_sft_binidx_steps.py` 定位实际文档，再用 `scripts/eval_sft_batch_loss.py` 对单文件权重计算对应目标 loss；命令参数见各自 `--help`。本地 [2.9B loss 排查记录](../RWKV7_3B_LOSS_DIAGNOSIS_GUIDE_CN.md) 记录了特定基座与模板的实验结论，应结合自己的模型/数据复验。
